# Nenolink AI Marker 1.0.3
# UI Navigation and State Specification

Status: Implementation specification  
Target: v1.0.3  
Scope: Navigation, application state, reset behaviour, preview behaviour and auxiliary tools

## 1. Purpose

This document defines the navigation and state model for Nenolink AI Marker 1.0.3. It is the authoritative specification for top-level navigation, content-type ownership, transitions, processing modes, preview behaviour, reset behaviour, Badges, Inspect File, Batch Processing, persistent visual settings, error handling and recovery.

Every reachable application state must be explicitly valid. The application must not rely on accidental combinations of active widgets, tabs or previously selected formats.

## 2. Core architecture

### 2.1 Four independent content types

The application has four independent content types:

1. Image
2. Video
3. PDF
4. PowerPoint / Slides

Each content type owns its selected file, processing mode, scope, selection, preview/navigation state, renderer/cache where applicable, status and warnings. A content type must never depend on another content type's active state.

### 2.2 MEDIA and DOCUMENTS are visual categories only

MEDIA groups Images and Video. DOCUMENTS groups PDF and PowerPoint / Slides. These categories do not own application state.

Examples of invalid leakage:
- Video inheriting Image workflow state
- PDF inheriting PowerPoint slide state
- Image displaying document controls
- Video displaying "Apply to slides"
- PDF displaying video Batch Processing

This architecture should allow future types such as Markdown or HTML without redesigning navigation.

## 3. Top-level navigation

Conceptual layout:

    NENOLINK AI MARKER                    Language | Reset | Guide

    MEDIA                 DOCUMENTS                 TOOLS
    Images   Video         PDF   PowerPoint          Badges   Inspect
    ------------------------------------------------------------------
                              WORKSPACE

Navigation elements must be horizontally aligned, compact and visually harmonious on the boundary between the dark header and grey workspace.

## 4. Top-level destinations

The only top-level destinations are:

1. Start
2. Image
3. Video
4. PDF
5. PowerPoint / Slides
6. Badges
7. Inspect File

Secondary controls may exist inside a content type but must not create invalid cross-format states.

## 5. Format switching

Navigation from one content type to another always creates a new working context. All 12 directed transitions between Image, Video, PDF and PowerPoint must be explicitly tested.

If active work exists, show a confirmation dialog before clearing it.

Example:

    Switch to PowerPoint?
    Your current PDF file, selection and preview will be cleared.
    [Cancel] [Continue]

Cancel preserves the current state exactly. Continue clears the old context, clears stale destination state, activates the destination and displays its clean initial state.

## 6. Format reset

A format reset clears:
- selected file and metrics
- preview and image references
- navigation/page/slide index
- processing mode and scope
- selected items and ranges
- renderer/cache
- temporary status and warnings

The destination then displays its clean start state.

A format reset must never produce a black/blank stale workspace, widgets or terminology from another type, an old filename, old page/slide number or stale selection.

## 7. Persistent visual settings

These preferences may survive internal processing-mode changes:
- selected AI disclosure badge
- selected own logo
- badge/logo size where applicable
- position
- margin
- opacity

Changing them must rerender the current valid preview without resetting the loaded file, scope or current preview position.

## 8. Hierarchical state model

Navigation is defined by two separate levels. They must not share ownership.

### 8.1 External FSM

The external FSM owns the active top-level destination:

    START
      +-- IMAGE
      +-- VIDEO
      +-- PDF
      +-- PPTX
      +-- BADGES
      +-- INSPECT

Selecting a different top-level content type terminates the current internal routine and starts the destination from a clean initial state.

For IMAGE, VIDEO, PDF and PPTX:

    external selection
        -> if active work: Cancel / Continue
        -> Continue: stop current internal routine
        -> clear current temporary working context
        -> initialise selected content type from scratch
        -> show its clean workspace
        -> start its internal routine

After Continue, the destination must be equivalent to selecting that destination immediately after fresh application startup.

The previous internal routine must no longer exist as an active or hidden workspace.

### 8.2 Internal routine

Each content type owns an internal routine. Internal operations never switch top-level content type.

Internal operations may update processing scope, preview position, visual properties or format-specific options. They preserve the active content type and, unless the operation explicitly selects a new file, preserve the loaded file.

An internal routine can be terminated only by:
- Global Reset
- an approved external transition to another top-level destination
- selecting a new file within the same content type, which creates a new file context

### 8.3 Reset vocabulary

Use these terms consistently:

    refresh_view()
        Visual/property change only.
        Preserve file, scope and preview position; rerender.

    reset_scope(new_scope)
        Same content type and same file.
        Replace scope, reset preview to the first relevant item, rerender.

    reset_external(new_type)
        Terminate current internal routine and temporary context.
        Initialise selected content type from scratch.

    global_reset()
        Terminate all temporary contexts.
        Return to the exact application startup state.

Do not use one reset operation as a substitute for another.

## 9. Document processing scope and preview

PDF and PPTX use the same conceptual model.

Processing scope and physical preview navigation are independent variables.

Conceptually:

    document
    active_scope
    current_preview_item

The processing scope answers:

    Which pages/slides receive the badge/logo?

The preview position answers:

    Which physical page/slide is currently displayed?

Changing scope must not restrict physical browsing. After any scope selection, the user can browse every physical page/slide with Previous/Next.

### 9.1 Scope choices

The supported scope choices are:

| UI choice | Normalised scope | Meaning |
|---|---|---|
| All | all items | Mark every page/slide |
| First | {1} | Quick action: mark only first page/slide |
| Selected | explicit set | Mark one or more explicitly selected pages/slides |
| Range | contiguous set | Mark all pages/slides in the specified interval |

"One" is removed because Selected can already contain exactly one item. "First" is intentionally retained as a fast shortcut for the normalised scope {1}.

The UI may distinguish First, Selected and Range, but the preview renderer should consume the normalised scope rather than maintain separate preview engines for each choice.

### 9.2 Common render rule

For the current physical preview item:

    render current page/slide
    if current item is in active_scope:
        render badge/logo
    else:
        render without badge/logo

For All, every valid item is in active_scope.

### 9.3 Scope reset

Any change in the scope selector performs an INTERNAL SCOPE RESET.

Preserve:
- loaded PDF/PPTX
- file metrics
- selected badge/logo
- size, position, margin and opacity
- top-level content type

Replace/recalculate:
- old active scope
- scope input/selection
- scope-specific temporary state
- preview/cache required for the old scope

Then:
1. calculate the new normalised scope;
2. reset preview position to the first relevant item;
3. immediately render that item;
4. keep Previous/Next available for browsing the whole document.

Default preview after scope change:

| Scope | New preview position |
|---|---|
| All | page/slide 1 |
| First | page/slide 1 |
| Selected 3,5,8 | page/slide 3 |
| Range 4-7 | page/slide 4 |

If Selected has no valid item yet, show an explicit selection state rather than a stale preview. Once the selection becomes valid, reset to its first selected item and render.

If Range is incomplete or invalid, show an explicit validation state. Once valid, reset to the first item in the range and render.

### 9.4 Physical browsing

Previous/Next changes only current_preview_item.

It must not modify active_scope.

Examples for a four-page PDF:

    First:
      page 1 -> badge
      page 2 -> no badge
      page 3 -> no badge
      page 4 -> no badge

    Selected = 1,3:
      page 1 -> badge
      page 2 -> no badge
      page 3 -> badge
      page 4 -> no badge

    Range = 2-3:
      page 1 -> no badge
      page 2 -> badge
      page 3 -> badge
      page 4 -> no badge

    All:
      every page -> badge

The same rule applies to PPTX slides.

### 9.5 Scope transition table

| Event | File | Scope | Preview position | Visual settings | Required action |
|---|---|---|---|---|---|
| Load document | New | All | 1 | Preserve/default | Render item 1 |
| All -> First | Preserve | {1} | 1 | Preserve | Reset scope + render |
| All/First/Range -> Selected | Preserve | selected set | first selected | Preserve | Reset scope + render |
| Selected set changes | Preserve | new selected set | first selected | Preserve | Reset scope + render |
| All/First/Selected -> Range | Preserve | range set | first in range | Preserve | Reset scope + render |
| Range values change | Preserve | new range set | first in range | Preserve | Reset scope + render |
| Any scope -> All | Preserve | all items | 1 | Preserve | Reset scope + render |
| Previous/Next | Preserve | Preserve | -1 / +1 | Preserve | Render physical item |
| Badge/logo/style change | Preserve | Preserve | Preserve | Update | Refresh current preview |

A scope change is never an external reset.

## 10. New file selection

Choosing a new file within the same content type creates a new file context. Clear the previous file-specific state and initialise the new file with default processing mode, metrics, navigation from the beginning, preview, clean scope and warnings/status. Persistent visual preferences may remain.

## 11. Preview invariant

After a valid supported file is selected, the application must display a valid preview or an explicit error explaining why preview cannot be displayed.

Never silently show a black workspace, blank stale workspace, old preview from another type or missing preview without explanation.

## 12. Batch Processing

Batch Processing is a processing mode, not a top-level content type. It belongs only to content types that support it.

Entering Batch Processing performs an internal mode reset, preserves applicable visual settings, clears incompatible single-file state and displays the correct Batch UI.

Document types must not expose media Batch Processing unless document batch support has explicitly been implemented and tested.

## 13. Badges

Badges is a global auxiliary tool, not owned by Image, Video, PDF, PowerPoint, MEDIA or DOCUMENTS.

It manages included disclosure badges, custom badges, own logos and locally stored badge/logo resources. These are persistent resources, not working state.

If entering Badges would discard active work, show a confirmation. Cancel preserves work. Continue clears the current working context and opens Badges. Stored badge/logo resources are never deleted by this reset.

Leaving Badges for any content type opens that type in its clean initial state. Badges must never remain as a hidden active workspace.

## 14. Inspect File

Inspect File is a global auxiliary tool:

    Inspect File -> Choose file -> Detect file type -> Supported inspector

Possible detected types include image, video, PDF, PowerPoint and unsupported/unknown.

Expose only functionality actually implemented. If PDF/PPTX metadata inspection is not implemented, do not pretend it is supported. Detection may instead report that the detected type is not currently supported.

Unknown/unsupported files must produce an explicit error.

Leaving Inspect for any content type opens that type cleanly. Inspect must not remain active underneath the new content type.

## 15. Global Reset

The top-level Reset button is the unconditional recovery mechanism and must ALWAYS remain available.

It must never be disabled or blocked by locked state, active format, processing mode, validation error, preview error, auxiliary tool, renderer state, invalid scope, selected file, Batch Processing, Badges, Inspect or any other reachable state.

Global Reset never requires confirmation.

It clears all Image, Video, PDF, PPTX, Batch, Inspect and auxiliary working state; files; previews; navigation; scopes; temporary selections; caches; warnings and status, and restores a clean usable Start state.

Persistent resources such as installed/custom badges, saved logos and localisation resources must not be deleted.

## 16. Global controls

Language, Reset and Guide must always work and remain accessible in every reachable application state. They must not depend on the active controller being valid or unlocked.

Temporary locking may disable unsafe conflicting operations, but must never lock the recovery path.

## 17. Recommended state ownership

    ApplicationController
        +-- ImageController
        +-- VideoController
        +-- PdfController
        +-- PptxController
        +-- BadgeManager
        +-- InspectController

Shared services may include BadgeService, LogoService, PreviewService, MetadataService, FileService and LocalizationService.

Shared implementation is encouraged where safe. Shared working state across content types is not.

## 18. Invalid states

These combinations must be impossible, not merely hidden:
- Video + Apply to slides
- Image + PDF page navigation
- PDF + Video Batch Processing
- PPTX + PDF page terminology
- Image/Video + Document Workspace
- PDF + media-only Inspect state
- PowerPoint + previous PDF filename
- Image + previous Video preview

Tests must assert that they cannot be reached.

| From | To | Expected |
|---|---|---|
| Image | Video | Clean Video start |
| Image | PDF | Clean PDF start |
| Image | PPTX | Clean PPTX start |
| Video | Image | Clean Image start |

| PDF | PPTX | Clean PPTX start |
| PPTX | Image | Clean Image start |
| PPTX | Video | Clean Video start |
| PPTX | PDF | Clean PDF start |

With active work, test both Cancel and Continue. Cancel preserves state exactly; Continue creates a clean destination.

## 20. Auxiliary transition matrix

At minimum test:
- Image/Video/PDF/PPTX -> Badges
- Badges -> Image/Video/PDF/PPTX
- Inspect -> Image/Video/PDF/PPTX

Where confirmation is required, test both Cancel and Continue. No transition may produce a black or stale workspace.

## 21. PDF scope and preview tests

Automated tests must verify the normalised-scope model rather than separate scope-owned preview sequences.

Required sequence:

    load PDF
    -> default All / preview 1
    -> First / preview 1
    -> browse to page 2: no badge
    -> Selected 2,4 / preview 2
    -> browse 1..N while scope remains {2,4}
    -> Range 3-5 / preview 3
    -> browse 1..N while scope remains {3,4,5}
    -> All / preview 1

At every valid step assert:
- PDF remains loaded
- active_scope is correct
- current_preview_page is correct
- Previous/Next can browse all physical pages
- badge/logo is shown iff current page is in active_scope
- visual settings are preserved
- top-level navigation and Global Reset remain available

## 22. PowerPoint scope and preview tests

Run the equivalent sequence for slides:

    load PPTX
    -> All
    -> First
    -> Selected
    -> Range
    -> All

Assert the same separation between active_scope and current_preview_slide.

## 23. External FSM tests

All 12 directed transitions among Image, Video, PDF and PPTX must be tested.

With active work:
- Cancel preserves the complete current internal routine.
- Continue terminates it and initialises the destination from scratch.

The destination after Continue must be state-equivalent to:

    fresh startup -> select destination

Required repeated sequence:

    Image -> PPTX -> PDF -> Video -> Image -> PDF -> PPTX

No previous file, preview, scope, navigation, renderer/cache or hidden workspace may survive an approved external transition.

Also test:
- PDF -> Badges -> Image
- PPTX -> Inspect -> Video
- Badges -> content type
- Inspect -> content type
- Global Reset from every top-level destination

## 23.1 Manual acceptance tests

Some behaviour must also be checked in the packaged Windows GUI because automated state tests cannot fully prove visible rendering and interaction.

Manual PDF:
1. Load a multi-page PDF; verify All is default and page 1 renders with badge.
2. Browse every page; every page shows the badge.
3. Choose First; view resets to page 1.
4. Browse every page; only page 1 shows the badge.
5. Choose Selected and enter multiple pages; view resets to first selected page.
6. Browse every page; only selected pages show the badge.
7. Change the Selected set; preview resets and immediately reflects the new set.
8. Choose Range; preview resets to range start.
9. Browse every page; only pages inside the range show the badge.
10. Change range values; preview resets and immediately reflects the new range.
11. Return to All; preview resets to page 1 and all pages show badge.

Manual PPTX:
Repeat the same sequence using slides.

Manual external navigation:
1. Load PDF and select a non-default scope.
2. Click PPTX.
3. Cancel: PDF must remain exactly unchanged.
4. Click PPTX again and Continue.
5. Verify all PDF file/scope/preview state is gone and clean PPTX start is shown.
6. Repeat through PPTX -> Image -> Video -> PDF and then again in another order.
7. Verify every approved external transition behaves like fresh startup followed by selecting the destination.

Manual recovery:
- Use Global Reset from PDF/PPTX scope states, Badges, Inspect and after repeated format switching.
- Verify the result matches fresh program startup.
- Verify Language, Reset and Guide remain available.

Manual Tools:
- Badges and Inspect must show only their own workspace.
- No Document Workspace or Media Workspace may remain visible underneath.
- Leaving either tool for any content type must initialise that destination cleanly.

## 24. Styling tests

For each supported format, load a valid file, navigate to a non-initial position where applicable, then change badge, logo, size, position, margin and opacity.

Expected: file and processing mode remain valid, current preview position remains valid and the preview rerenders without a format reset.

## 25. Preview errors

If preview cannot be generated:
- show an explicit error
- do not leave an unexplained black workspace
- keep Global Reset available
- allow another file or format to be chosen

A preview failure must not trap the application.

## 26. Navigation visual acceptance

Navigation is accepted only if MEDIA, DOCUMENTS and TOOLS labels/controls share a harmonious baseline/vertical centre, no secondary row sits arbitrarily lower in the grey workspace, minimum supported window size remains usable and unnecessary vertical whitespace is avoided.

## 27. Start state

Startup and Global Reset lead to one explicitly defined Start state with no selected file, stale preview, previous scope, page/slide or hidden active workspace.

If the product intentionally defaults to Image, document and test that explicitly.

## 28. Core invariants

### Visible-state invariant
The visible UI must correspond to the active state. Active format, workspace, terminology, file, preview, navigation and scope must never describe different content types.

### User-action invariant
- New content type -> complete format reset -> clean destination
- New file -> file-context reset -> initialise new file
- New document scope -> reset_scope -> preserve file/styling -> normalise scope -> reset preview to first relevant item -> rerender
- Physical Previous/Next -> preserve scope -> change preview item -> rerender
- Styling change -> preserve context -> rerender current preview
- Global Reset -> clear all working state -> Start

### Persistence invariant
Persistent resources (standard/custom badges, saved logos, application/localisation resources) are separate from temporary working state (file, preview, page/slide, scope, selection, Batch/Inspect session, warnings/status).

## 30. Implementation rule

Do not solve violations by adding isolated widget-specific callback patches unless behaviour is genuinely widget-specific.

Prefer central transitions such as:

    switch_content_type(...)
    reset_format_context(...)
    reset_scope(...)
    reset_file_context(...)
    global_reset(...)

Exact names may differ. State transitions must be central, explicit and testable.
